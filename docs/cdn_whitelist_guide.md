# Руководство по настройке VK Cloud CDN и Yandex Cloud CDN (Обход «белых списков»)

Когда мобильные операторы или ТСПУ включают режим жестких «белых списков» (разрешен доступ только к российским крупным сервисам и CDN-сетям внутри РФ), прямое соединение с зарубежным VPS может блокироваться даже при использовании `VLESS-Reality`.

В этом случае используется **реальное проксирование через CDN-провайдера из белого списка**:
`Клиент (РФ) -> Edge-сервер VK/Yandex CDN (РФ, белый список) -> Ваш VPS (<BASE_DOMAIN>, Германия)`

---

## Как это работает в Server-Combain

1. **Nginx** на нашем сервере слушает внутренний порт `127.0.0.1:8443` (трафик приходит от `sniproxy` с `443/tcp`).
2. Специально выделенные секретные пути (сгенерированные при установке и доступные через `combain info`):
   - `/<XHTTP_VK_PATH>` (XHTTP) и `/<WS_VK_PATH>` (WebSocket fallback) — для **VK Cloud CDN**.
   - `/<XHTTP_YA_PATH>` (XHTTP) и `/<WS_YA_PATH>` (WebSocket fallback) — для **Yandex Cloud CDN**.
3. Трафик с этих путей Nginx прозрачно проксирует на локальные инбаунды **Xray (`3x-ui`)** без буферизации (`proxy_buffering off`, поддержка HTTP/2 и `Upgrade` для WebSocket).
4. После подключения по CDN-домену (выданному провайдером или привязанному CNAME) трафик клиента выглядит для провайдера как обычное HTTPS-обращение к узлу VK Cloud или Yandex Cloud.

---

## 1. Настройка в Yandex Cloud CDN

### Шаг 1. Подготовка источника (Origin)
1. Перейдите в консоль **Yandex Cloud** -> сервис **Cloud CDN**.
2. Создайте **Группу источников (Origin Group)**:
   - Название: например `origin-combain`.
   - Источник: ваш домен `<BASE_DOMAIN>` (используйте домен, а не IP, чтобы работал SNI на нашем `sniproxy` и проверка TLS-сертификата!).
   - Порт источника: `443`.

### Шаг 2. Создание CDN-ресурса
1. Нажмите **Создать ресурс**:
   - **Доменное имя (CNAME):** либо используйте технический домен `*.cdn.yandex.net` / выданный CNAME, либо свой поддомен (например `ycdn.<BASE_DOMAIN>`, привязанный через CNAME к выданному Yandex адресом).
   - *Совет по скрытности:* использование стандартного поддомена на домене провайдера (`*.gcdn.co` / `*.yandex.net`) или отдельного нейтрального домена позволяет не светить основной домен клиента на первом этапе рукопожатия.
2. **Настройки взаимодействия с источником:**
   - Протокол запроса к источнику: **HTTPS**.
   - Заголовок `Host`: выберите передачу кастомного заголовка `Host` = `<BASE_DOMAIN>` (критически важно, чтобы `sniproxy` направил трафик в Nginx, а Nginx выбрал нужный `server_name`!).
3. **Кэширование (Обязательно отключить / минимизировать!):**
   - Включите опцию **Игнорировать кэширование** или задайте время жизни кэша `0 секунд` (иначе CDN может отдавать кэшированные пустые ответы вместо проксирования).
   - Включите пересылку всех HTTP-методов (`GET`, `POST`, `PUT`, `HEAD`, `OPTIONS`) — это критически важно для работы **XHTTP**.
   - Отключите сжатие (Gzip/Brotli) на уровне CDN для путей прокси.
   - Включите проксирование заголовков и поддержку WebSocket (если используете WS-резерв).

---

## 2. Настройка в VK Cloud CDN

### Шаг 1. Создание CDN-ресурса
1. Войдите в личный кабинет **VK Cloud** -> раздел **CDN**.
2. Нажмите **Создать ресурс**:
   - **Источник (Origin):** укажите `<BASE_DOMAIN>:443` (протокол **HTTPS**).
   - Если VK Cloud требует отдельный домен для раздачи, укажите ваш домен/поддомен для CDN или используйте предоставляемый сервисом технический домен.

### Шаг 2. Настройка заголовков и правил
1. **Заголовок Host:** укажите `<BASE_DOMAIN>` (должен совпадать с доменом, на который выпущен SSL-сертификат на вашем VPS).
2. **SSL / TLS:** выберите режим **HTTPS** и включите перенаправление HTTP -> HTTPS (или оставьте HTTPS-only).
3. **Параметры кэширования:**
   - Установите **Время кэширования (TTL)** = `Отключено / 0 сек` (либо создайте правило для пути `/<XHTTP_VK_PATH>*` и `/<WS_VK_PATH>*` с отключенным кэшем).
   - Разрешите методы `GET` и `POST` (для XHTTP).
   - Включите поддержку **HTTP/2** и **WebSockets** (в дополнительных опциях).
   - Отключите сжатие на стороне CDN (чтобы не ломать бинарные потоки Xray).

---

## 3. Проверка и подключение в клиенте (v2rayNG / NekoBox / Hiddify / Happ)

После настройки ресурса в панели CDN:
1. Введите выданный CDN-домен в меню комбайна (`combain` -> **Управление VPN** -> **Настроить домены CDN**).
2. Скрипт автоматически сгенерирует готовые ссылки `vless://...`:
   - `address`: домен вашего CDN (или проверенный чистый Edge-IP из пула VK/Yandex CDN).
   - `sni` / `host`: домен вашего CDN-ресурса.
   - `path`: `/<XHTTP_VK_PATH>` или `/<XHTTP_YA_PATH>`.
   - `type`: `xhttp` (рекомендуемый основной транспорт) или `ws` (запасной вариант для старых клиентов).
3. Проверьте прохождение запроса: при открытии `https://<CDN_DOMAIN>/` в браузере должна открыться наша игра-заглушка «Киберпанк Космо-Ранер». Это подтверждает, что CDN корректно видит источник через `sniproxy` и Nginx.
4. После этого импортируйте `vless://` ссылку в клиент на базе актуального `Xray-core` (например, **v2rayNG** или **NekoBox**).

---

## 4. Что делать при смене IP сервера (после блокировки)

- В большинстве случаев при блокировке IP нашего VPS **домен `<BASE_DOMAIN>` не меняется**.
- Достаточно обновить `A`-запись `<BASE_DOMAIN>` у регистратора (указать новый IPv4) и запустить `combain` -> **Быстрая смена IP**.
- **VK Cloud CDN** и **Yandex Cloud CDN** автоматически подхватят новый IP вашего источника после обновления DNS-кэша (обычно 1–5 минут), перенастраивать клиентские ссылки `vless://` для CDN вообще не потребуется!
