# Руководство по развертыванию кластера Combain-Mesh

**Combain-Mesh** — децентрализованная P2P-сеть управления поверх приватного WireGuard-туннеля (`wg-mesh0`, `10.99.0.0/24`) для связки **2–3 зарубежных exit-нод** (DE / NL / FI) и **1 российского ретранслятора** (`ru_relay`).

Ключевые возможности:
- **Без единой точки отказа (No Single Master):** каждая нода хранит локальную SQLite-базу с LWW-синхронизацией (Last-Write-Wins) и обменивается дельтами каждые 15 секунд по HMAC-подписанному API (`22777/tcp` только внутри `wg-mesh0` и `lo`).
- **Автоматический failover:** если любая нода перестаёт отвечать более 45 секунд, она помечается `offline` и автоматически исключается из подписок клиентов (`/u/<token>`, `/u-json/<token>`, `/api/v1/client/bootstrap`).
- **Персональные подписки для семьи и друзей:** лимит устройств (`max_devices` по HWID), срок действия (`expires_at`), мгновенное отключение и сброс устройств с любой ноды кластера.
- **Встроенный RU-обход (Split-Tunneling):** Госуслуги, MAX (`max.ru`, `oneme.ru`), VK, Сбер, Т-Банк и российские ресурсы идут напрямую (`direct`).

---

## 1. Архитектура и распределение IP в кластере

Рекомендуемая схема адресации в подсети `10.99.0.0/24` (порт WireGuard `51829/udp`):

| Нода | Роль (`MESH_ROLE`) | Mesh IP (`wg-mesh0`) | Назначение |
| :--- | :--- | :--- | :--- |
| `de-1` | `exit` | `10.99.0.1` | Основной зарубежный выход (Германия) |
| `nl-1` | `exit` | `10.99.0.2` | Резервный зарубежный выход (Нидерланды) |
| `fi-1` | `exit` | `10.99.0.3` | Дополнительный выход (Финляндия, опционально) |
| `ru-msk-1` | `ru_relay` | `10.99.0.10` | Российский ретранслятор (входная точка и каскад на exit) |

> **Безопасность фаервола:** Модуль добавляет правила строго в изолированную цепочку `COMBAIN-PROTECT`: `51829/udp` открыт для WireGuard-рукопожатий, а порт API `22777/tcp` разрешён **только** на `lo` и `wg-mesh0` (снаружи полностью закрыт).

## 2. Пошаговое развертывание кластера

### Шаг 1. Базовая установка на каждом сервере
На каждой ноде (`de-1`, `nl-1`, `ru-msk-1`) выполните стандартную установку Server-Combain:
```bash
combain install
```

### Шаг 2. Инициализация первой ноды (`de-1`)
1. Откройте меню кластера:
   ```bash
   combain mesh
   ```
   *(или пункт `9` в главном меню `combain`)*
2. Выберите **`1) Инициализировать эту ноду в Combain-Mesh`**:
   - Роль: `1` (`exit`)
   - Имя ноды: `de-1`
   - Mesh IP: `10.99.0.1`
   - Порт WG: `51829`, порт API: `22777`
   - `MESH_SECRET`: нажмите `Enter` для автоматической генерации 32-символьного ключа.
3. Сохраните выведенную **Карточку ноды** (Публичный IP, `WG Public Key`, `Mesh IP`, `MESH_SECRET`).

### Шаг 3. Инициализация остальных нод (`nl-1`, `ru-msk-1`)
На `nl-1` и `ru-msk-1` также выполните `combain mesh` -> пункт `1`, указав:
- для `nl-1`: роль `exit`, имя `nl-1`, Mesh IP `10.99.0.2`;
- для `ru-msk-1`: роль `ru_relay`, имя `ru-msk-1`, Mesh IP `10.99.0.10`;
- **`MESH_SECRET`:** вставьте **тот же самый секрет**, который был сгенерирован на `de-1`.

### Шаг 4. Связывание нод между собой (Join Peer)
На каждой паре нод выполните `combain mesh` -> **`2) Подключить соседнюю ноду (Join Peer)`** и введите данные из карточки соседа (Публичный IP, WG Public Key, Mesh IP, домен).

> **Важно:** WireGuard требует взаимного добавления пиров (`de-1` <-> `nl-1`, `de-1` <-> `ru-msk-1`, `nl-1` <-> `ru-msk-1`).

Проверьте статус туннеля и кластера через **`4) Статус кластера, нод и wg-mesh0`**:
- в `wg show wg-mesh0` у пиров должно появиться время `latest handshake`;
- в `node-list` все ноды должны иметь статус `online`.

## 3. Настройка каскада RU-Relay -> Exit

На ноде `ru-msk-1` выберите `combain mesh` -> **`6) Настройка каскада RU-Relay -> Exit поверх wg-mesh0`**:
- Модуль сгенерирует готовый JSON-шаблон `/etc/server-combain/mesh/ru_relay_cascade.json` для маршрутизации клиентского трафика с российской ноды на `10.99.0.1` (или другую exit-ноду) поверх зашифрованного `wg-mesh0`, с прямым выходом (`direct-ru`) для Госуслуг, MAX, VK и банков РФ.
- Если основная exit-нода уйдёт в `offline`, клиентская подписка автоматически переключится на оставшиеся здоровые ноды кластера.

## 4. Выдача подписок семье и друзьям

Создать пользователя можно на **любой** ноде кластера — изменения синхронизируются на все серверы автоматически:

1. Выполните `combain mesh` -> **`3) Пользователи и подписки`** -> **`1) Создать пользователя`**.
2. Укажите:
   - имя (например `mama`, `alex`);
   - лимит устройств (`max_devices`, по умолчанию `3`);
   - срок действия в днях (`30`, `90` или `0` для бессрочного доступа);
   - заметку.
3. Модуль выдаст готовые персональные ссылки и QR-код:
   - **Base64 URI:** `https://<BASE_DOMAIN>/u/<sub_token>`
   - **Xray JSON (рекомендуется для v2RayTun, включает RU-обход):** `https://<BASE_DOMAIN>/u-json/<sub_token>`
   - **Bootstrap API (для фирменного приложения):** `https://<BASE_DOMAIN>/api/v1/client/bootstrap` + `X-Sub-Token: <sub_token>`

### Управление доступом
В том же подменю (`3`) доступны:
- **Продление срока** (`user-extend`) — добавляет дни к текущей дате окончания.
- **Сброс HWID** (`user-reset-devices`) — очищает привязанные устройства (если пользователь сменил телефон/ПК).
- **Отключение / включение** (`user-disable` / `user-enable`) — мгновенно блокирует подписку и удаляет UUID пользователя из 3x-ui на всех нодах кластера.

## 5. Интеграция будущего приложения (Android / Windows) с `/api/v1/client/bootstrap`

Будущее 2-кликовое приложение подключается к **любому** домену из кластера (`mirrors`) по HTTPS (443 порт, проксируется Nginx на `127.0.0.1:22777`):

### Запрос
```http
GET /api/v1/client/bootstrap HTTP/2
Host: <BASE_DOMAIN>
X-Sub-Token: <персональный_sub_token_пользователя>
X-HWID: <уникальный_идентификатор_устройства>
```
*(Также поддерживается передача токена через query-параметр `?token=<sub_token>`).*

### Успешный ответ (`200 OK`)
```json
{
  "account": {
    "username": "alex",
    "expires_at": 1798761600,
    "max_devices": 3,
    "used_devices": 1
  },
  "smart_dns": [
    {
      "node": "de-1",
      "doh": "https://dns.example.com/dns-query",
      "dot": "tls://dns.example.com:853",
      "ip": "203.0.113.10"
    }
  ],
  "mirrors": [
    "https://de.example.com",
    "https://nl.example.com"
  ],
  "sub_url": "https://de.example.com/u/<sub_token>",
  "sub_json_url": "https://de.example.com/u-json/<sub_token>"
}
```

### Обработка кодов ответа в приложении
- **`200 OK`:** сохранить список `mirrors` (резервные домены для обхода блокировки основного домена), применить `smart_dns` и загрузить актуальный профиль с `sub_json_url` (передавая `X-HWID`).
- **`403 Forbidden`:** подписка отключена, истёк срок `expires_at` либо превышен лимит `max_devices` (показать пользователю сообщение обратиться к администратору для продления или сброса HWID).
- **Таймаут / сетевая ошибка:** автоматически повторить `GET /api/v1/client/bootstrap` на следующем домене из кэшированного массива `mirrors`.
