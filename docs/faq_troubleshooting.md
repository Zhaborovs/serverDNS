## 1. IP-адрес VPS заблокирован РКН / ТСПУ — что делать?

Server-Combain изначально спроектирован так, чтобы пережить блокировку IP за 2–5 минут без потери клиентов, сертификатов и подписок. Выберите сценарий, который подходит под вашу ситуацию.

### Сценарий А. Хостер выдал новый IP на том же сервере (`comb change-ip`)
1. В панели DNS регистратора (например, **REG.RU**) измените `A`-записи домена на новый IPv4 сервера:
   - `vpn.example.com` -> `203.0.113.10` (новый IP)
   - `dns.vpn.example.com` -> `203.0.113.10` (если используется раздельная схема)
   > **Совет на будущее:** заранее выставите у регистратора **`TTL = 300`** (5 минут) для `A`-записей. Тогда после смены IP кэш DNS у провайдеров обновится за считаные минуты, а не за сутки.
2. Подключитесь к серверу по SSH и выполните:
   ```bash
   comb change-ip
   ```
   *(или пункт **`2`** в интерактивном меню `comb`)*
3. Скрипт автоматически:
   - определит новый внешний IPv4 и сохранит его в `/etc/server-combain/state.env`;
   - безопасно остановит **AdGuard Home**, заменит старый IP на новый во всех правилах `AdGuardHome.yaml` и запустит сервис обратно;
   - обновит `Endpoint` во всех клиентских `.conf` и пересоберёт ссылки `vpn://` для **AmneziaWG 3.1**;
   - перезапустит **sniproxy**, пересоберёт подписки (`/sub/` и `/sub-json/`) и обновит сводку `last_summary.txt`.
4. Клиентам Xray достаточно нажать **«Обновить подписку»** в `v2RayTun` — домен остался прежним, ссылки продолжают работать! Для AmneziaWG 3.1 и Telegram Proxy выдайте обновлённые QR-коды из `comb qr`.

### Сценарий Б. Полный переезд на другой VPS (`comb migrate`)
Если нужно сменить хостера или локацию, перенесите всю инфраструктуру (сертификаты Let's Encrypt, БД `3x-ui`, конфиги AdGuard Home, ключи AmneziaWG, `sniproxy.conf` и даже нативные контейнеры AmneziaVPN) шифрованным архивом `.tar.gz.enc` (AES-256-CBC, паролем служит имя файла без расширения).

#### Способ 1: Временный Drag&Drop веб-портал (живёт ровно 1 час)
1. **На старом сервере** запустите `comb migrate` -> **`1) Создать архив бэкапа`**.
   - На вопрос *«Поднять временную ссылку на скачивание через браузер (на 1 час)?»* ответьте `y`.
   - Скачайте зашифрованный архив `.tar.gz.enc` себе на компьютер по выданной одноразовой ссылке.
2. **На новом чистом VPS (Ubuntu 24.04 LTS)** установите базовый стек (см. [README](../README.md)) и запустите `comb migrate` -> **`2) Восстановить из бэкапа через Drag&Drop веб-страницу (активна 1 час)`**.
   - Если домен ещё не переведён, портал автоматически поднимется на временном случайном порту по IP нового сервера (`http://203.0.113.10:<port>/?token=...`).
   - Откройте ссылку в браузере и перетащите скачанный `.tar.gz.enc`.
3. Новый сервер сам расшифрует архив, восстановит сертификаты/БД/ключи, поднимет все контейнеры и вызовет `comb change-ip` для привязки к новому IP.
4. Переведите `A`-записи в REG.RU (`TTL = 300`) на IP нового VPS.

#### Способ 2: Прямой перенос по SSH/SCP (без скачивания на ПК)
На новом VPS выполните `comb migrate` -> **`4) Стянуть бэкап напрямую со старого сервера по SSH/SCP`** и введите IP, SSH-порт и пользователя (`root`) старого сервера. Новый VPS сам создаст архив на старом, скачает его и развернёт всю систему.

*(Также доступен пункт **`3`** — восстановление по прямой HTTPS-ссылке или локальному пути к файлу `.tar.gz.enc`.)*

### Сценарий В. У вас кластер `Combain-Mesh` (автоматический failover)
Если у вас развёрнуто 2–3 зарубежные ноды в кластере **Combain-Mesh** (см. [руководство по кластеру](mesh_cluster_guide.md)):
- При блокировке или падении одной ноды остальные серверы кластера автоматически помечают её `offline` через **45 секунд** и исключают из клиентских подписок (`/u/<token>`, `/u-json/<token>`, `/api/v1/client/bootstrap`).
- Пользователям достаточно обновить подписку в `v2RayTun` (или переключиться на второй узел в списке) — перерыва в работе не будет.
- Спокойно замените IP на проблемной ноде или перенесите её, пока остальной кластер держит нагрузку.

## 2. Умный DNS + ByeDPI/Zapret или полноценный VPN: что выбрать?

Оба подхода отлично дополняют друг друга — вы не обязаны выбирать только один.

| Критерий | Умный DNS (AdGuard + SNIProxy) + ByeDPI/Zapret | Полноценный VPN (`v2RayTun` / `AmneziaWG 3.1`) |
| :--- | :--- | :--- |
| **Что обходит** | Зарубежные геоблокировки (ChatGPT, Gemini, Claude, Copilot, Spotify, Autodesk) + локальное замедление DPI (YouTube, Discord) | Любые блокировки по IP, SNI, протоколам; жёсткие белые списки мобильных операторов (через VK/Yandex CDN) |
| **Задержка (пинг) в играх и РФ-сервисах** | Нулевой оверхед — трафик идёт напрямую | Минимальная задержка, российские домены идут напрямую благодаря 2-уровневому RU split-tunneling |
| **Нагрузка на канал VPS** | Минимальная (через VPS идут только домены из `geo_domains.list`) | Весь зарубежный трафик идёт через VPS |
| **Скрытие вашего IP** | Нет (для обычных сайтов виден ваш реальный IP) | Да (зарубежные сайты видят IP сервера) |
| **Работа банков / Госуслуг / MAX** | Работают полностью напрямую без доп. настроек | Работают напрямую через встроенный RU-обход + Per-App Bypass |
| **Где лучше использовать** | Домашний ПК (Windows 11) на постоянной основе | Смартфоны (мобильный интернет / Wi-Fi), поездки, жёсткие блокировки |

**Оптимальная стратегия:**
- На **Windows 11** держите постоянно включённым **Умный DNS (DoH)** (в паре с ByeDPI/Zapret при необходимости), а `v2RayTun` / `AmneziaVPN` включайте точечно, когда нужно скрыть IP или открыть ресурс, заблокированный по IP.
- На **Android / iOS** используйте **`v2RayTun`** с JSON-подпиской (`/u-json/<token>` или `/sub-json/<token>`) и настроенным Per-App Bypass (см. [Быстрый старт для клиентов](quickstart_clients.md#2-android-v2raytun--подписка-ru-обход-и-per-app-bypass)).

## 3. Почему на Windows вместо флагов стран показываются буквы `US` / `DE` / `NL`?

В подписках Server-Combain названия узлов формируются автоматически из 2-буквенного ISO-кода страны сервера (например, `DE` -> `🇩🇪`, `NL` -> `🇳🇱`, `US` -> `🇺🇸`), в формате `🇩🇪 Combain-Direct-XHTTP [vpn.example.com]`.

- На **Android, iOS, macOS и Linux** системные шрифты эмодзи отображают эти символы (Unicode Regional Indicator Symbols) как цветные флажки стран.
- В **Windows 10 / Windows 11** компания Microsoft **намеренно исключила глифы национальных флагов** из системного шрифта **Segoe UI Emoji** (чтобы не участвовать в политических спорах вокруг спорных территорий). Поэтому вместо флага Windows отображает двухбуквенный код региона (`DE`, `NL`, `US`).

Это **чисто визуальная особенность шрифта Windows** — она никак не влияет на подключение, скорость или маршрутизацию.

## 4. Как работают `comb update` и `comb update --cluster`?

Server-Combain умеет безопасно обновлять весь стек одной командой **без потери состояния, пользователей, сертификатов и настроек** (`/etc/server-combain/state.env`, БД `3x-ui`, `mesh.db`, ключи AWG и кастомные домены сохраняются).

### Локальное обновление одного сервера: `comb update`
*(Также доступно через `comb service` -> пункт `1` или главное меню `comb` -> пункт `10` -> `1`)*

Последовательно выполняет:
1. **`git pull --ff-only`** в `/opt/server-combain` (обновляет скрипты, пресеты, шаблоны, исправляет права и CRLF, обновляет симлинки `comb` / `combain`).
2. Перезагружает модули в памяти и при необходимости автодоопределяет **IPv6** (`SERVER_IPV6`) и **страну сервера** (`SERVER_COUNTRY`).
3. Перерендеривает конфигурацию **Nginx** и делает безопасный `nginx -t && nginx -s reload`.
4. Синхронизирует пресеты геоблока и блокировки RU-телеметрии в **AdGuard Home** и **sniproxy** (включая IPv6 dual-stack).
5. Переприменяет инбаунды в **3x-ui / Xray** и пересобирает подписки (`/sub/` и `/sub-json/`).
6. Если включён **Combain-Mesh** — перезапускает `combain-mesh.service` и запускает `sync-now`.
7. Обновляет сохранённую сводку `/etc/server-combain/last_summary.txt`.

### Синхронное обновление всего кластера: `comb update --cluster`
*(Также доступно через `comb service` -> пункт `2`)*

1. Сначала полностью обновляет текущий сервер (`comb update`).
2. Затем отправляет **HMAC-подписанную команду `cluster-update`** через приватную сеть `wg-mesh0` на все онлайн-ноды кластера **Combain-Mesh** — они синхронно обновляют свой код и переприменяют конфигурации.

### Обновление Docker-образов (Nginx, 3x-ui, MTProto, SOCKS5)
Команда `comb update` обновляет код и конфиги комбайна, не скачивая заново тяжёлые Docker-образы. Когда вы захотите обновить сами образы контейнеров, откройте `comb service` -> **`3) Обновить Docker-образы`** (выполнит `docker compose pull && docker compose up -d`).

## 5. Частые проблемы и их решение

### 5.1. SSL / Certbot: DNS не успел обновиться
**Симптом:** при установке на шаге проверки DNS скрипт показывает `[WAIT] vpn.example.com -> сейчас 'пусто', ожидается '203.0.113.10'`, либо Certbot возвращает ошибку валидации домена.

**Решение:**
- Убедитесь, что у регистратора (REG.RU / Cloudflare и др.) прописаны `A`-записи для `vpn.example.com` (и `dns.vpn.example.com` в раздельной схеме) на точный IPv4 сервера.
- Если используется Cloudflare — на время выпуска сертификата **отключите оранжевое облако (Proxy -> DNS only)**.
- Убедитесь, что **порт `80/tcp`** не закрыт внешним фаерволом хостера (Certbot в режиме `--standalone` проверяет домен по `80/tcp`).
- Подождите 2–5 минут (пока обновится кэш `1.1.1.1` / `8.8.8.8`) и нажмите `Enter` в цикле проверки DNS.
- Проверить автопродление сертификата можно командой `certbot renew --dry-run` (хуки автопродления настроены так, чтобы **не** останавливать `sniproxy` на `443/tcp`).

### 5.2. Конфликт на порту 443 (`Address already in use`)
**Симптом:** служба `sniproxy` не запускается, в `journalctl -u sniproxy` видно `bind ...:443 failed: Address already in use`.

**Причины и решение:**
- На сервере ранее был установлен системный `nginx`, `apache2`, `caddy` или другой прокси, занявший `443/tcp`.
- Проверьте, кто занимает порт:
  ```bash
  ss -tulnp | grep ':443'
  ```
- Остановите и отключите конфликтующий сервис (например, `systemctl disable --now nginx apache2`), после чего перезапустите `sniproxy`:
  ```bash
  systemctl restart sniproxy
  ```
- В норме внешний порт `443/tcp` должен слушать **только `sniproxy`** (контейнер `combain-nginx` слушает внутренний `127.0.0.1:8443`).

### 5.3. Поведение IPv6 (Dual-Stack)
Как Server-Combain работает с IPv6:
- **Входящий трафик (`sniproxy`):** если у VPS есть внешний глобальный IPv6 (например, `2001:db8::1`), `sniproxy` автоматически биндится строго на конкретный адрес `[2001:db8::1]:443` (а не на wildcard `[::]:443`), чтобы не конфликтовать с `0.0.0.0:443` при `net.ipv6.bindv6only=0`. В `ip6tables` открываются `443/tcp` и `ipv6-icmp`.
- **Подписки:** при наличии IPv6 в подписках автоматически появляются резервные IPv6-маршруты (`Combain-Direct-XHTTP-IPv6`, `Combain-Direct-WS-IPv6`). Если у клиента на телефоне или роутере нет IPv6, просто используйте обычные IPv4-маршруты (`Combain-Direct-XHTTP` / `Combain-Direct-WS`).
- **Исходящий трафик (Xray и AdGuard Home):** внутри Xray для исходящих соединений используется стратегия `UseIPv4` (это избавляет от кривой маршрутизации IPv6 у хостеров и капч Google), а AdGuard Home блокирует утечки `AAAA` и `HTTPS/SVCB` для геоблокированных доменов, чтобы Умный DNS стабильно работал через IPv4 `sniproxy`.

### 5.4. Смена телефона/ПК и лимит устройств (сброс HWID)
**Симптом:** пользователь в кластере `Combain-Mesh` купил новый телефон или переустановил Windows, и подписка `/u/<token>` / `/u-json/<token>` возвращает ошибку `403 Forbidden` (превышен лимит устройств `max_devices`).

**Решение (выполняется с любой ноды кластера):**
1. Запустите `comb mesh` -> **`5) Пользователи и подписки`** -> **`4) Сбросить привязанные устройства (HWID)`**.
2. Введите имя пользователя (например, `alex`).
3. Привязка старых устройств мгновенно очистится и синхронизируется по всему кластеру — пользователь сможет снова обновить подписку на новом устройстве.

*(Прямой CLI-вызов: `python3 /opt/server-combain/scripts/mesh/combain_mesh.py user-reset-devices --state-dir /etc/server-combain --username <имя>`.)*

### 5.5. Как посмотреть логи, статус служб и сводку `comb info`
Если нужно быстро продиагностировать сервер:

- **Сводка всех ссылок, паролей и DoH-команды:**
  ```bash
  comb info        # интерактивное меню по разделам (DNS / Xray / AWG / TG / QR)
  comb info --all  # вывести всю сводку целиком (копия в /etc/server-combain/last_summary.txt)
  ```
- **Единый экран здоровья всех служб, контейнеров и открытых портов (`443` / `853`):**
  ```bash
  comb service     # выбрать пункт 4) Статус всех служб, контейнеров и портов
  ```
- **Логи конкретных компонентов:**
  - `sniproxy`: `journalctl -u sniproxy -n 50 --no-pager`
  - `AdGuardHome`: `journalctl -u AdGuardHome -n 50 --no-pager`
  - `combain-mesh`: `journalctl -u combain-mesh -n 50 --no-pager`
  - Контейнеры Docker (`combain-nginx`, `combain-3xui`, `combain-awg`, `combain-mtproto`, `combain-socks5`):
    ```bash
    docker ps
    docker logs --tail 50 combain-nginx
    docker logs --tail 50 combain-3xui
    docker logs --tail 50 combain-awg
    ```
- **Проверка статуса кластера и WireGuard-туннеля:**
  - `comb mesh` -> **`6) Статус кластера, нод и wg-mesh0`** (показывает `combain-mesh.service`, `wg show wg-mesh0`, `node-list` и `cascade-target`).
